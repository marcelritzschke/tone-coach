# Tone Coach

Mandarin tone practice: the learner records a phrase and sees their pitch contour
against a native reference. Roadmap and specifications live in
[`docs/PLAN.md`](docs/PLAN.md) — read it before starting a milestone, adding an
endpoint, or changing the analysis pipeline. Commands and endpoints are in the two
package READMEs.

## Decisions worth knowing before you change something

**Tones are authored offline, never computed at request time.** `data/phrases.json`
is generated by `scripts/build_phrases.py` and committed; CI asserts the two still
match. A grapheme-to-phoneme mistake is then caught once in review instead of served
to a learner on every request. Change the corpus by editing
`data/phrases.source.tsv` and rebuilding, never by hand-editing the JSON.

**No single g2p engine is trusted.** The generator runs `pypinyin` and `g2pM` and
writes every disagreement to `data/phrases.review.md`. Neither is reliable alone —
g2pM misreads 银行 as `yin2 xing2`, pypinyin gets three-syllable tone-3 chains wrong.
Entries in that file need a human ear; 17 are currently outstanding.

**Sandhi is product content, not preprocessing.** Each syllable carries both
`citationTone` (as written) and `surfaceTone` (as said). The gap between them is a
large part of what the app teaches, so it stays visible in the data and the UI.

**Half-third tone is load-bearing.** A tone 3 before any non-tone-3 falls low without
rising (`realization: "half"`); only a phrase-final tone 3 dips (`"full"`). Scoring
that expects a dip everywhere marks correct connected speech as wrong. A test asserts
a surface 3-3 pair can never exist, since sandhi makes it unreachable.

**Score against the reference contour, not idealised tone shapes.** The reference is
ground truth for that phrase in that context, so it carries sandhi and coarticulation
for free. Idealised shapes are for *naming* an error in words, never for measuring it.

**Reference audio and syllable timing are separate seams.** `services/voice.py`
produces audio; timing is derived from the audio itself. An earlier design took both
from one vendor, so losing the vendor cost both — and the destination is human
recordings, which have no timestamps at all.

## Gotchas

**Never run `next build` while `next dev` is live.** They share `.next/`, so the
build overwrites the dev server's chunks and every asset 404s — the page renders as
bare DOM with no CSS. Recovery is `rm -rf .next` and restart. Use a separate
`distDir` to verify a build while someone is testing.

**Port 8000 is occupied on the maintainer's machine** by an unrelated service. Run
the backend elsewhere and pass `NEXT_PUBLIC_API_URL` to the frontend to match.

**`NEXT_PUBLIC_*` is inlined at build time**, so changing the API URL needs a rebuild
or a dev-server restart, not just a new environment value.

**Chart.js with `parsing: false` reads `.x` off each item raw**, which turns a
malformed point into a crash rather than a gap. Unvoiced frames are `{x, y: null}`;
a bare `null` in the array throws. This shipped once — it compiled, linted and built
clean, and only failed in front of a human.

## Verifying a change

Green means all of: `ruff check`, `ruff format --check`, `mypy`, `pytest` in
`backend/`, and `lint`, `typecheck`, `build` in `frontend/`. CI runs exactly these.

A green build is not evidence the page renders. There are no frontend tests yet
(M2 adds them), so anything touching the practice screen needs a real recording made
in a browser before it is called done.
